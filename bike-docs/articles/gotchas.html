Gotchas

This page documents every known pitfall that cost real debugging time. Organized by phase. Closed issues are marked.

These gotchas are canonical debugging shortcuts. Future developers (and dispatched agents): read the relevant section before touching the code.

Phase 1 Gotchas (Physics derivation)

Gotcha 1: Inertia-tensor rotation direction inverted in derive.py

Status: Closed (fixed in Phase 1)

Moore's RearFrame/FrontFrame inertia is computed from Meijaard's via R_y(lambda) * I * R_y(lambda)^T where the rotation goes C-frame to world, not the other way around. The eigenvalue benchmark caught it (~16% error on a benchmark eigenvalue at v=0).

If a large systematic discrepancy appears after a derivation change, suspect this first.

Gotcha 2: Pitch convention at upright is Pitch = SteerAxisTilt, NOT Pitch = 0

Status: Closed (fixed in Phase 1)

The front-wheel-on-ground holonomic constraint with Roll = Steer = 0 solves to q5 = lambda for the canonical benchmark geometry. BicycleState.UprightStationary correctly sets this.

Gotcha 3: Coordinate singularity at exactly Roll = 0

Status: Open (by design — documented workaround)

The dependent yaw rate in the nonlinear EOM contains a 1/sin(Roll) factor. Evaluating at exact upright produces NaN.

Workarounds applied:

  • LinearizationExtractor perturbs by baseRoll = 1e-3 rad before central differences.
  • All behavioral and determinism tests perturb the initial state by 1e-3 rad in Roll.
  • BikeWorld.AddBike applies Roll = 1e-3 automatically.

Gotcha 4: ControlInputs.DriveTorque sign convention is inconsistent

Status: Open (documented — scheduled for Phase 3 fix)

The docstring says "Negative = brake", but the generated EOM treats positive DriveTorque as decelerating. Phase 1 behavioral test Scenario 5 papered over this by negating the test's input.

FeelPreset.Default uses DriveTorqueScale = -3.0 to compensate. Any new input source must apply the same compensation until the EOM mapping is fixed in Phase 3.

Gotcha 5: KanesMethod returns a 6×6 augmented mass matrix

Status: Closed (by design)

KanesMethod returns a 6×6 augmented mass matrix when nonholonomic constraints are present, not the 3×3 reduced system the plan originally assumed. The generated code uses an in-place LU solve with stackalloc Span<double> to keep allocations zero.

Gotcha 6: Generated C# is huge

Status: Closed (by design)

WhippleEOM.cs is ~1100 lines of straight-line FLOPs after SymPy CSE. Do not hand-edit; regenerate via tools/eom-codegen/. See Build & Test Reference.

Phase 2 Gotchas (Unity integration)

Gotcha 7: Moore frame is +Z DOWN, not up

Status: Closed for unity-v2 (PhysicsBridge round-trip tests gate this). Open for legacy unity/.

The comment on BicycleParameters.ComZ says "paper places +Z up" — true for Meijaard's paper, but the Moore frame used internally by the generated EOM has +Z pointing down into the ground. PhysicsBridge.ToUnity maps physics (X, Y, Z) to Unity (X, Z, -Y).

If a body shows up underground in Unity, suspect this first.

Gotcha 8: BicycleState.UprightAtSpeed needs Pitch perturbation

Status: Open (documented workaround in BikeWorld.AddBike)

BehavioralScenarioTests.MakeInitialState sets s.Pitch = p.SteerAxisTilt + 1e-5 to break a 0/0 in the holonomic constraint at exact upright. Without this extra perturbation the simulator NaNs by the second step.

BikeWorld.AddBike applies both the Roll and Pitch perturbations automatically. Any new direct consumer of UprightAtSpeed must apply them too.

Gotcha 9: SteerTorque sign convention is also inverted

Status: Open (documented — scheduled for Phase 3 fix)

Same issue as Gotcha 4 but for steer. DebugInputProvider works around it with _steerTorqueScale = -1.5. FeelPreset.Default uses SteerTorqueScale = -1.5.

Gotcha 10: Whipple model has no ground-contact constraint for off-nominal states

Status: Open (Phase 4 territory)

When Roll grows past ~30–40°, the model is outside its valid range. The integrator continues until Roll = 0 is crossed and the 1/sin(Roll) singularity NaNs everything. BikeWorldRunner auto-resets on NaN AND on |Roll| > 1 rad.

The bike does not physically rest on the ground after falling — that requires a contact extension (Phase 4).

Gotcha 11: MCP for Unity's read_console does not surface Debug.Log entries

Status: Closed (workaround documented)

Only errors, warnings, and exceptions come through read_console. For runtime print debugging, tail ~/AppData/Local/Unity/Editor/Editor.log directly — it captures everything.

Gotcha 12: manage_prefabs create_from_gameobject cannot overwrite an existing prefab path

Status: Closed (workaround documented)

It silently creates a sibling <name> 1.prefab and leaves the old one in place. Pattern that works: ask the user to delete old, rename new, then mcp__UnityMCP__refresh_unity --mode force.

Gotcha 13: Prefab/scene reference IDs reset when GameObjects are deleted and recreated

Status: Closed (workaround documented)

If you manage_gameobject delete RearFrame and create a new one, every component that referenced the old RearFrame Transform goes null. Re-wire via set_property after rebuilding.

Gotcha 14: Unity primitive Cylinder's mesh +Y axis is its height axis

Status: Closed (workaround documented)

For wheel visualization, treat the wheel GameObject as a parent driven by physics, with a child Cylinder primitive rotated (0, 0, 90) so the cylinder's height aligns with the spin axis. Driving the wheel directly with BodyPose.Orientation (which includes accumulated spin angle) makes the cylinder symmetry axis tumble.

Gotcha 15: Yaw sign bug in the kinematics

Status: FIXED 2026-05-14

Root cause: SymPy's frame.dcm(N) returns a world→body rotation matrix, but the C# QuatFromMatrix helper expected body→world. The codegen was passing C.dcm(N) directly, producing an inverse rotation. Fixed by a transpose in tools/eom-codegen/emit_csharp.py.

Regression test: BehavioralScenarioTests.RearFrameForwardAlignsWithRearWheelVelocity_Under_Sustained_Steer.

Phase 2.6 Gotchas (Unity v2 rebuild)

Gotcha 16: Do NOT pass -quit to Unity batchmode when using -runTests

Status: Closed (documented)

Unity Test Framework manages its own exit lifecycle. Passing -quit causes Unity to shut down during initial asset import, before tests execute.

  • Correct for -runTests: Unity.exe -batchmode -nographics -projectPath <path> -runTests -testPlatform EditMode -testResults <xml> -logFile <log> — no -quit.
  • Correct for -executeMethod: include -quit.

Gotcha 17: Local Unity 6000.3.15f1 rewrites ProjectVersion.txt on every project open

Status: Closed (documented)

The pinned version in unity-v2/ProjectSettings/ProjectVersion.txt is 6000.0.40f1 (LTS). Local development on 6000.3.15f1 works but always run git restore unity-v2/ProjectSettings/ProjectVersion.txt before committing.

Gotcha 18: Unity Quaternion is single-precision float; orientation round-trip tests need 1e-6 tolerance

Status: Closed (documented, tests use separate tolerance constants)

Position round-trips can stay at 1e-9 (sign flips + component swaps only). Orientation round-trips need 1e-6 tolerance due to float precision loss in cos(pi/4) / sin(pi/4).

Gotcha 19: Unity Editor -executeMethod requires fully qualified namespace

Status: Closed (documented)

-executeMethod SandboxSceneBuilder.BuildAll fails silently with exit code 1. Correct form: -executeMethod Bicycle.Editor.SandboxSceneBuilder.BuildAll.

Gotcha 20: Inspector wiring is not yet automated for Sandbox.unity

Status: Open — scheduled for v2.1 polish

The scene exists with a BikeWorldRunner GameObject, but the BikeConfig list is empty. Press-Play in Editor will not yet show a moving bike until a BikeConfig is wired via Inspector. The PlayMode test bypasses this via runtime construction.

Gotcha 21: KeyboardInputSource.FeelPreset null fallback uses 1.0 scales, NOT the negative defaults

Status: Open — scheduled for v2.1 polish

When no BikeFeelPresetAsset is assigned, the source defaults to scale = 1.0 — which means W decelerates and steer is inverted (per Gotchas 4 + 9). For correct keyboard mapping, you MUST assign a BikeFeelPresetAsset with explicit SteerTorqueScale = -1.5, DriveTorqueScale = -3.0.
