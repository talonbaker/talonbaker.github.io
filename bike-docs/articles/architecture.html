Architecture

The project is split into three layers: a physics core library, a world orchestrator library, and a Unity presentation layer. Each layer has a strict contract with the layer below it.

Hard rules

These rules are invariants enforced by design. Violating them introduces the singleton / shared-mutable-state patterns that make multiplayer impossible:

  1. Only BikeWorldRunner ever holds a BikeWorld reference. Nothing else touches the physics clock.
  2. No Unity code calls BicycleSimulator.Step() directly. All simulation goes through BikeWorld.
  3. No Unity component is a singleton. Every system takes a BikeId at Awake or subscribes to an event. Singletons break N-bike operation.
  4. The pose stream contract is BodyPose. Unity does not bake in flat-ground assumptions. The 3D Vec3D Position + QuatD Orientation contract is valid for future terrain work.

Tick model

The physics runs at a fixed 250 Hz (4 ms timestep). Unity's variable frame rate is decoupled from the physics step:

  • BikeWorldRunner.FixedUpdate() calls BikeWorld.Step(Time.fixedDeltaTime, inputs) once per physics step. Time.fixedDeltaTime is set to 0.004 in Project Settings.
  • BikeVisualizer.Update() interpolates between the previous and current snapshot for smooth rendering at any frame rate ("Fix Your Timestep!" pattern by Glenn Fiedler).
  • The interpolation parameter alpha = (Time.time - lastFixedTime) / Time.fixedDeltaTime is computed per frame, kept in [0, 1].

Event causal ordering

BikeWorld.Step() follows a two-phase event firing strategy (spec §6.1):

  1. Phase 1: step all simulators, capture (prev, current) snapshot pairs.
  2. Phase 2: fire OnBikeSnapshot for each bike — after ALL bikes have stepped. This ensures observers see a consistent world-state slice.

Bump events (OnBikeBump) fire immediately when injected, not deferred, because they represent a causal per-bike occurrence rather than a world-state slice.

Allocation-free design

The hot path (250 Hz per bike) is allocation-free:

  • BicycleSimulator.Step() uses stackalloc for the LU solve and a cached delegate to avoid per-step GC pressure.
  • BikeSnapshotEventArgs is cached per-bike inside BikeWorld and updated in-place before each event raise. Subscribers must copy data synchronously — storing a reference across event calls will see stale data.
  • The _stepBuffer list backing array is grown once on AddBike and never shrinks.

The allocation-free invariant is CI-gated: a test runs 100,000 simulator steps and asserts GC.GetAllocatedBytesForCurrentThread() is unchanged.

Coordinate systems

Moore frame (+Z down): The generated EOM and all BodyPose.Position values use the Moore frame where +Z points down into the ground. +X is forward, +Y is right, +Z is down.

Unity frame (+Y up): Unity uses right-hand coordinates with +Y up, +Z forward.

PhysicsBridge.ToUnity() maps Moore (X, Y, Z) to Unity (X, Z, -Y) — i.e., physics +Z (down) maps to Unity -Y. See Gotcha 7 for the full story and the round-trip test that gates this.

Bicycle.Physics public API surface

Type Role
BicycleSimulator Owns one bike's state. Step, Reset, CurrentSnapshot, State, Parameters.
BicycleParameters POD geometry + inertia. MeijaardBenchmark and GameDefault static presets.
BicycleState 11-double POD. UprightStationary and UprightAtSpeed factory methods.
ControlInputs 3-double POD: SteerTorque, DriveTorque, RiderLeanTorque.
BicycleSnapshot Per-step output: four BodyPose values + ForwardSpeed + SimulationTime.
BodyPose World-space position + orientation + velocities for one rigid body.
ParametersJson Save/Load helpers (non-Unity builds only).

Bicycle.World public API surface

Type Role
BikeWorld N-bike orchestrator. AddBike, RemoveBike, Step, Reset, three events.
BikeId Stable per-bike identity wrapping an int.
BikeSnapshot Per-bike snapshot: four BodyPose values + ForwardSpeed + SimulationTime.
BumpEvent Obstacle bump descriptor: Tier (intensity 1-3) + LeanSign (±1).
FeelPreset Tunable feel parameters. Default matches Phase 2 empirical tuning.
