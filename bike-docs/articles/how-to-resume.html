How to Resume

This page explains how to pick up the project from a clean checkout on any machine.

Step 0: Sanity check

git status
git log --oneline -5
gh pr list --state open

Confirm you're on the right branch and that the baseline tests still pass before touching anything.

Picking up Phase 1 (Physics core)

Phase 1 is complete and merged. No active work. If you need to verify the baseline:

dotnet test src/Bicycle.Physics.Tests    # expect 67/67 passing

If the eigenvalue gate fails, see Gotchas 1-6 — inertia tensor rotation direction is the most likely culprit.

Picking up Phase 2 / 2.5 (legacy unity/)

Phase 2 and 2.5 are complete and merged to main. The legacy unity/ project is reference-only.

  1. Open unity/ in Unity Hub with Unity 2022.3.50f1 (pinned in unity/ProjectSettings/ProjectVersion.txt).
  2. Open Assets/Bicycle/Scenes/DeskCourse.unity for the playable level, or Sandbox.unity for the feel test bench.
  3. Press Play.
  4. Verify baseline: dotnet test src/Bicycle.Physics.Tests must report 67/67 passing.

If the MCP for Unity package is installed (com.coplaydev.unity-mcp in unity/Packages/manifest.json), you can drive the Editor remotely via MCP tools. Set the active instance with set_active_instance and check mcpforunity://editor/state for readiness. Note: Debug.Log output does NOT appear in read_console — tail ~/AppData/Local/Unity/Editor/Editor.log instead.

Picking up Phase 2.6 (unity-v2)

The v2.0 Walking Skeleton is merged. Open PRs are the active work surface.

gh pr list --state open                   # current PRs
gh issue list --state open                # current Stories / Decisions
git checkout main
git pull
  1. Read the design spec: docs/superpowers/specs/2026-05-19-unity-v2-rebuild-design.md
  2. Open unity-v2/ in Unity Hub with Unity 6000.0.40f1 (LTS, pinned in unity-v2/ProjectSettings/ProjectVersion.txt).
  3. Open Assets/Bicycle/Scenes/Sandbox.unity and press Play. The bike should initialize and sit at upright.
  4. Unity batchmode verification: & "C:\Program Files\Unity\Hub\Editor\6000.3.15f1\Editor\Unity.exe" -batchmode -nographics -projectPath unity-v2 -runTests -testPlatform EditMode -testResults out.xml -logFile - (see Gotcha 16 — no -quit with -runTests).
  5. Restore ProjectVersion.txt before committing: git restore unity-v2/ProjectSettings/ProjectVersion.txt (see Gotcha 17).

Picking up feel iteration (Phase 3 territory)

The Phase 2 + 2.5 + 2.6 baseline is on main. Open PRs are the active work surface for feel-tuning.

Before starting new feel work:

  1. Check gh pr list --state open — confirm no in-flight PR already covers the same area.
  2. Play-test the current baseline to identify the actual feel bottleneck.
  3. Use the superpowers:brainstorming skill for any new feel-design work.

The current FeelPreset.Default values (SteerTorqueScale = -1.5, DriveTorqueScale = -3.0) are the empirically tuned baseline from Phase 2. Diverge from them only after a play-test identifies a specific problem.

Picking up multiplayer (Phase 5)

Phase 5 design is locked in docs/superpowers/specs/2026-05-16-networked-multiplayer-design.md. Implementation is gated on:

  • v2.1 Epic landing (active)
  • Phase 5.0 wire-format PR merging (DRAFT PR #8 on feat/multiplayer-foundation-1)

Do not start Phase 5 implementation until those gates clear.

Just running existing work

# Build everything
dotnet build Bike.sln

# Physics tests (expect 67/67)
dotnet test src/Bicycle.Physics.Tests

# World tests (expect 5/5)
dotnet test src/Bicycle.World.Tests

# Perf baseline (~1 minute)
dotnet run -c Release --project src/Bicycle.Physics.Benchmarks

# Replay a recorded input trace to CSV
dotnet run --project src/Bicycle.Physics.PlaybackHarness -- inputs.json out.csv

# Build the docs site
docfx docs/docfx/docfx.json

# Serve the docs locally (opens at http://localhost:8080)
docfx docs/docfx/docfx.json --serve
