Class BicycleSimulator

Namespace
Bicycle.Physics
Assembly
Bicycle.Physics.dll

Integrates the full nonlinear Whipple bicycle equations of motion for a single bike. Allocation-free on the hot path — all intermediate storage is stack-allocated or pre-allocated at construction time.

Typical usage:

var sim = new BicycleSimulator(BicycleParameters.GameDefault);
sim.Step(0.004, new ControlInputs { DriveTorque = -3.0 });
ref readonly var snap = ref sim.CurrentSnapshot();
// snap.RearFrame.Position gives the rear-frame centre-of-mass in world space (Moore frame)

AddRearWheelSpinDelta(double)

One-shot external impulse: add deltaRadPerSec to the rear-wheel spin rate. Used by game-side bump physics to bleed forward speed when the bike brushes an obstacle. NOT used inside the integrator; consumers call this between Step() calls. Convention: RearWheelSpinRate is negative for forward motion, so positive delta = slowdown.

ClampSteer(double)

Clamps Steer to ±maxAbsRadians and zeroes SteerRate only when the wheel is being driven further into the limit. One-sided so the wheel can still swing back toward neutral once it hits the wall. Intended to be called once per step, after Step(), for game-feel steer-stop behavior. Like rolling friction, this is applied OUTSIDE the integrator on purpose.

CurrentSnapshot()

Returns the world-space poses of all four rigid bodies (Moore frame, +Z down) for the current state. The snapshot is cached and recomputed lazily only when the state has changed since the last call. Returns a reference to avoid struct copies on the hot path.

Reset(in BicycleState)

Resets the simulator to the given state, clearing the snapshot cache. Call this after constructing UprightAtSpeed(double, in BicycleParameters) to apply the Roll and Pitch perturbations required to avoid the coordinate singularity (gotchas #3 and #8). BikeWorld.AddBike in the Bicycle.World package does this automatically — prefer it over calling Reset directly in game code.

Step(double, in ControlInputs, double)

Advances the simulation by dt seconds using a single RK4 step. Hot path — allocation-free. Callers should use dt = 0.004 (250 Hz).

rollingFrictionCoefficient applies a post-step linear decay to the rear-wheel spin rate: spinRate *= (1 - k * dt). Defaults to 0 (frictionless) so existing callers see unchanged behavior. Applied outside the integrator to preserve the Meijaard eigenvalue benchmark.
