Namespace Bicycle.Physics

Classes

BicycleSimulator

Integrates the full nonlinear Whipple bicycle equations of motion for a single bike. Allocation-free on the hot path — all intermediate storage is stack-allocated or pre-allocated at construction time.

Typical usage:

var sim = new BicycleSimulator(BicycleParameters.GameDefault);
sim.Step(0.004, new ControlInputs { DriveTorque = -3.0 });
ref readonly var snap = ref sim.CurrentSnapshot();
// snap.RearFrame.Position gives the rear-frame centre-of-mass in world space (Moore frame)
Integrator

Sealed RK4 integrator over BicycleState. Caller supplies the derivative function. All scratch buffers are fields on this instance — no allocations during Step(ref BicycleState, double, DerivativeProvider).

ParametersJson

JSON serialization helpers for BicycleParameters. Not compiled into Unity builds (guarded by #if !UNITY_5_3_OR_NEWER) because Unity's JSON tooling (JsonUtility or Newtonsoft.Json) is used there instead.

Structs

BicycleParameters

Complete parameter set for the canonical Whipple bicycle model. Field values for MeijaardBenchmark follow Meijaard et al. 2007 Table 1.

BicycleSnapshot

World-space pose and velocity of all four bicycle bodies, plus scalar summary fields. This is the contract the (future) Unity layer reads from.

BicycleState

Integrated state of a bicycle. 8 generalized coordinates (Pitch is the dependent coordinate, kept consistent with the front-wheel-on-ground holonomic constraint by the integrator) plus the 3 independent generalized speeds (RollRate, SteerRate, RearWheelSpinRate).

Bit-blittable POD: MemoryMarshal.AsBytes(ref state) is safe.

BodyPose

World-space pose and velocity of a single rigid body.

ControlInputs

External torques applied to the bicycle for one integration step. All values default to zero. Positive sign conventions match Meijaard 2007.

IMPORTANT — sign-convention inversions (gotchas #4 and #9): The generated EOM treats positive DriveTorque as decelerating (sign is inverted from typical expectation). Similarly, positive SteerTorque steers left from the rider's perspective. FeelPreset.Default in the Bicycle.World package compensates with negative scales (-3.0 for drive, -1.5 for steer). A proper fix is deferred to Phase 3.

FrameBodyParameters

Inertia properties of a frame body (RearFrame or FrontFrame), expressed in the reference posture defined by Meijaard 2007 (upright, zero steer, ground at z = 0). Assumes a vertical symmetry plane, so only Ixx, Ixz, Iyy, Izz are needed. Mass-centre coordinates ComX, ComZ are in the reference frame's origin/axes.

StateDerivative

Time derivative of BicycleState. Internal type used by the integrator to carry intermediate stage values during RK4. Same layout as BicycleState so callers can iterate in lock-step.

WheelBodyParameters

Inertia properties of an axisymmetric wheel (RearWheel or FrontWheel).
