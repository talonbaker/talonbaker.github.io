Classes

BikeWorld

Orchestrates N independent bike simulations behind a clean event-driven contract. Unity-side code calls Step(double, IReadOnlyDictionary<BikeId, ControlInputs>) once per fixed update, then reacts to OnBikeSnapshot, OnBikeBump, and OnBikeReset events on the main thread.

Hard rules (see spec §6.1):

  1. Only one MonoBehaviour (BikeWorldRunner) ever holds a BikeWorld reference.
  2. No Unity code calls Step(double, in ControlInputs, double) directly.
  3. Every method takes a BikeId so N-bike operation is supported from day 1.

Event causal ordering (spec §6.1):

  • Snapshot events fire AFTER all simulators have stepped (consistent world-state slice).
  • Bump events fire immediately when injected (per-bike causal ordering).

Allocation-free design:

  • OnBikeSnapshot args are cached per-bike and updated in-place.
  • OnBikeBump and OnBikeReset args are always newly allocated (rare events, not on the hot path).
  • The step snapshot buffer is a List whose backing array is grown on AddBike and never shrinks, so no per-step heap allocation occurs.

Structs

BikeId

Stable identity for a single bike within a BikeWorld. Wraps an int; two BikeId values are equal iff their underlying integers are equal.

BikeSnapshot

World-space poses of all four bicycle bodies for a single bike at a single point in simulation time. This is the per-bike equivalent of BicycleSnapshot extended to carry identity information.

BumpEvent

Describes a single bump interaction between a bike and an obstacle. Tier classifies the bump intensity (e.g. 1 = small tap, 2 = medium, 3 = hard). LeanSign indicates which side the bike was leaning toward on impact: +1 = leaning right, -1 = leaning left.

FeelPreset

Pure-C# POD that describes all tunable parameters controlling how a bike "feels" to the rider. This struct is constructed directly in xUnit tests and converted from a Unity ScriptableObject (BikeFeelPresetAsset) in the presentation layer.

Placeholder set of 5 fields for v2.0; the full ~30-field surface is introduced incrementally in v2.9 as feel-tuning progresses.

Polarity conventions match the gotcha documentation: SteerTorqueScale negative = steer-right on right-arrow (gotcha #9) DriveTorqueScale negative = accelerate on W (gotcha #4)
