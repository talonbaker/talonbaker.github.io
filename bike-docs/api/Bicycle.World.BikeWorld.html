Class BikeWorld

Bicycle.World

Bicycle.World.dll

Orchestrates N independent bike simulations behind a clean event-driven contract. Unity-side code calls Step(double, IReadOnlyDictionary<BikeId, ControlInputs>) once per fixed update, then reacts to OnBikeSnapshot, OnBikeBump, and OnBikeReset events on the main thread.

Hard rules (see spec §6.1):

  1. Only one MonoBehaviour (BikeWorldRunner) ever holds a BikeWorld reference.
  2. No Unity code calls Step(double, in ControlInputs, double) directly.
  3. Every method takes a BikeId so N-bike operation is supported from day 1.

Event causal ordering (spec §6.1):

  • Snapshot events fire AFTER all simulators have stepped (consistent world-state slice).
  • Bump events fire immediately when injected (per-bike causal ordering).

Allocation-free design:

  • OnBikeSnapshot args are cached per-bike and updated in-place.
  • OnBikeBump and OnBikeReset args are always newly allocated (rare events, not on the hot path).
  • The step snapshot buffer is a List whose backing array is grown on AddBike and never shrinks, so no per-step heap allocation occurs.

AddBike(BikeId, in BicycleParameters, in FeelPreset)

Register a new bike with the given physics parameters and feel preset. The bike starts in an upright-at-zero-speed state with small Roll and Pitch perturbations applied (CLAUDE.md gotchas #3 and #8) to avoid the coordinate singularity at exact upright:

  • Roll = 1e-3 rad: avoids the 1/sin(Roll) singularity in the EOM's yaw rate.
  • Pitch = SteerAxisTilt + 1e-5: breaks the holonomic-constraint 0/0 at exact upright. See Phase 1 BehavioralScenarioTests.MakeInitialState for the canonical reference implementation of both perturbations.

Step(double, IReadOnlyDictionary<BikeId, ControlInputs>)

Advance all registered bikes by dt seconds, applying the control inputs from inputs (bikes absent from the dictionary receive zero inputs). Raises OnBikeSnapshot for each bike after ALL bikes have been stepped (consistent world-state slice per spec §6.1).

Hot path — allocation-free. See class XML doc for the design constraints.

public void Step(double dt, IReadOnlyDictionary<BikeId, ControlInputs> inputs)

Parameters

dt double

Integration step in seconds (typically 0.004 for 250 Hz).

Map of per-bike inputs for this step. Read-only; callers may reuse the same dictionary across frames.

OnBikeSnapshot

Raised after each Step(double, IReadOnlyDictionary<BikeId, ControlInputs>) for every registered bike, carrying the previous and current snapshots.

IMPORTANT: Do not store a reference to the BikeSnapshotEventArgs across event invocations. The same object is reused each step (allocation-free design). Copy data synchronously inside the handler.
